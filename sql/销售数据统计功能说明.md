# 销售数据统计功能说明

## 功能概述

销售数据统计功能用于统计每个销售人员的业绩数据，包括成交金额、应收金额、已开票金额和回款金额。该功能采用缓存机制，每日凌晨自动更新数据，提高查询效率。

## 数据库表

### 表名：jl_sales_data_statistic_cache

该表用于缓存销售人员的统计数据。

#### 表结构

```sql
CREATE TABLE IF NOT EXISTS `jl_sales_data_statistic_cache` (
    `id` BIGINT(20) NOT NULL AUTO_INCREMENT COMMENT 'ID',
    `user_id` BIGINT(20) NOT NULL COMMENT '用户ID',
    `user_name` VARCHAR(100) DEFAULT NULL COMMENT '用户名称',
    `order_amount` DECIMAL(10, 2) DEFAULT 0.00 COMMENT '成交金额',
    `accounts_receivable` DECIMAL(10, 2) DEFAULT 0.00 COMMENT '应收金额',
    `invoice_amount` DECIMAL(10, 2) DEFAULT 0.00 COMMENT '已开票金额',
    `payment_amount` DECIMAL(10, 2) DEFAULT 0.00 COMMENT '回款金额',
    `statistic_date` VARCHAR(8) DEFAULT NULL COMMENT '统计日期（YYYYMMDD格式）',
    `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `creator` BIGINT(20) DEFAULT NULL COMMENT '创建人',
    `updater` BIGINT(20) DEFAULT NULL COMMENT '更新人',
    `deleted` TINYINT(1) DEFAULT 0 COMMENT '是否删除',
    `tenant_id` BIGINT(20) DEFAULT 0 COMMENT '租户ID',
    PRIMARY KEY (`id`),
    KEY `idx_user_id` (`user_id`),
    KEY `idx_statistic_date` (`statistic_date`),
    KEY `idx_deleted` (`deleted`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='销售数据统计缓存表';
```

## 定时任务配置

### 任务类：SalesDataStatisticCacheJob

- **执行时间**：每天凌晨 00:30
- **Cron表达式**：`0 30 0 * * ?`
- **任务说明**：自动更新销售数据统计缓存

### 配置步骤

1. 在后台管理系统中找到"定时任务管理"
2. 添加新的定时任务：
   - 任务名称：销售数据统计缓存更新
   - 任务处理器：SalesDataStatisticCacheJob
   - Cron表达式：`0 30 0 * * ?`
   - 状态：开启

## API接口

### 1. 获取销售数据统计

**接口地址**：`GET /statistic/sales/sales-data-statistic`

**请求参数**：
- `userIds`：用户ID数组（可选，不传则查询所有销售人员）
- `startTime`：开始时间（可选）
- `endTime`：结束时间（可选）

**响应示例**：
```json
{
  "code": 0,
  "data": [
    {
      "userId": 1,
      "userName": "张三",
      "orderAmount": 100000.00,
      "accountsReceivable": 50000.00,
      "invoiceAmount": 80000.00,
      "paymentAmount": 50000.00,
      "updateTime": "2025-10-13 00:30:00"
    }
  ],
  "msg": "操作成功"
}
```

### 2. 手动刷新缓存

**接口地址**：`GET /statistic/sales/sales-data-statistic-refresh`

**说明**：手动触发缓存更新，用于测试或紧急更新场景。

## 数据计算逻辑

### 成交金额（orderAmount）
统计该销售人员所有已签订合同的总金额。

**计算公式**：
```
成交金额 = SUM(已签订合同.price)
```

### 应收金额（accountsReceivable）
统计该销售人员应收但未收的金额。

**计算公式**：
```
应收金额 = 成交金额 - 合同已收金额
```

### 已开票金额（invoiceAmount）
统计该销售人员所有已开票（非未开票状态）的总金额。

**计算公式**：
```
已开票金额 = SUM(开票记录.price) WHERE status != '未开票'
```

### 回款金额（paymentAmount）
统计该销售人员所有已审核的回款总金额。

**计算公式**：
```
回款金额 = SUM(回款记录.receivedPrice) WHERE status = '已审核'
```

## 用户体验优化

### 1. **友好的空数据提示**
当首次查询或缓存数据为空时：
- 自动弹出确认对话框，询问是否刷新数据
- 用户可选择"立即刷新"或"取消"
- 避免用户不知道为什么没有数据

### 2. **智能的Loading提示**
刷新数据时：
- 显示全屏Loading遮罩层
- 提示文字："正在刷新数据，请稍候..."
- 防止用户重复点击

### 3. **并发控制**
- 使用 `volatile` 标识防止并发更新
- 如果已经在更新中，再次刷新会提示："数据正在更新中，请稍后再试"
- 保证数据一致性

### 4. **精确的时间显示**
- 表格上方显示数据更新时间（精确到秒）
- 示例：`数据更新时间：2025-10-13 00:30:15`

### 5. **智能的筛选提示**
- 如果筛选条件下没有数据，提示："当前筛选条件下暂无数据"
- 如果是首次查询没有数据，才提示刷新

## 注意事项

1. **数据更新时机**：缓存数据每日凌晨自动更新，如需实时数据可使用"手动刷新"功能
2. **权限控制**：需要有 `jl:subject-group:query` 权限才能访问相关接口
3. **性能优化**：通过缓存机制避免实时计算，提高查询效率
4. **并发安全**：使用状态标识防止并发更新，保证数据一致性
5. **用户友好**：提供友好的提示和Loading状态，提升用户体验
